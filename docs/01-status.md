## 2. 已经打通的链路

1. **低功耗框架**：RTC 1 h 周期 + PB4 PIR 上升沿 + LPTIM 三路唤醒，`Lpm_GotoDeepSleep(TRUE)` 深睡；
2. **联网**：ESP8266 AT 指令状态机（EN/RST 硬复位 + `AT` 轮询 + 超时复位），UART0 9600 8E1；
3. **云端**：MQTT 连接、发布一帧 JSON、订阅 NTP 主题对时；
4. **配网**：ESP8266 开 softAP + 内置 HTTP 服务，浏览器 POST `{"ssid":"…","pass":"…"}` → 存 Flash 0xFE00 页 → 复位生效；长按配网键（PB5）擦除参数；
5. **采集**：ADC 顺序扫描两路 + 中断取结果 + 5 次平均，电池电压 → 电量百分比；
6. **稳定性兜底**：所有 AT 交互 10 s 超时，超时直接 `NVIC_SystemReset()`。

## 4. 代码与硬件的不一致（重要）

| 项 | 工程/代码 | 硬件（原理图 & PCB） |
| --- | --- | --- |
| 芯片 | `HC32L130J8TA`（64 KB Flash / 8 KB RAM） | `HC32L110C6PA`（TSSOP20，丝印 `HC32-L110C6PA_V1.5`） |
| Flash 算法 | `FlashHC32L130_64K.FLM` | 实际 32 KB，作者 readme 也写着"目标 flash 选 32k" |
| 烟雾传感器 | 代码里有 MQ 系列公式 `Smog_GetPPM()` | 原理图上**没有**烟雾传感器接口 |

也就是说：**这份固件是给 L130 板子编译的，装在 L110 板子上跑**。引脚能对上（P2x/P3x ↔ PAx/PBx 是同一批引脚在 L110/L130 上的不同命名），但存储空间和下载算法要对齐，否则烧进去会越界。

## 5. 作者 readme 与代码的矛盾

`firmware/readme.txt` 里写的几件事，代码并没有按它实现：

| readme 说 | 代码实际 |
| --- | --- |
| 白天 6:00–21:00 每小时上报 | `Time_WrokStart=0x09`、`Time_WrokEnd=0x06`，白天只剩 06:00–08:59 |
| 有烟雾传感器（休眠时切断其供电） | 代码只切 ESP 供电，没有烟雾传感器 |
| 长按配网按键 5 s 进入配网 | 中断里轮询 200×10 ms = 2 s，且提前松开会取消 |

这些不是"错误"，是两代设计留下的痕迹。下一版建议以代码为准，重写 readme。
